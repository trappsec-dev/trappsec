# Changelog

All notable changes to trappsec are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/).

## Unreleased

### Changed: one API across Python, Node and Go

The SDKs now share names, units and option shapes. Every old form below keeps working; Node and Go log nothing for them except where noted.

- **Default responses have setters:** `default_response(...)` / `default_unauthenticated_response(...)` (Go: `DefaultResponse(ResponseConfig)` / `DefaultUnauthenticatedResponse(ResponseConfig)`) take the same arguments as `respond` / `if_unauthenticated`, including `template`. Assigning to `default_responses` still works; Go's `SetDefaultAuthenticated` / `SetDefaultUnauthenticated` are deprecated.
- **Node:** watch fields take `{ default, intent }` like Python (`defaultValue` still accepted); `trigger(req, reason, { intent, metadata })` (positional still accepted); the request extractors are `ts.request` with `user_agent`, as in Python (`requestContext` / `userAgent` remain aliases).
- **Node: `close(timeout)` is in seconds** (default 5), like Python and like Node's own `heartbeat_interval`. Values of 1000 or more are still read as milliseconds, with a one-time warning.
- **Go: optional arguments are optional.** `watch.Body("x", trappsec.Default(false), trappsec.Intent("PrivEsc"))`, `watch.Query("debug")`, `ts.Trigger(c, reason, trappsec.Intent(...), trappsec.Metadata(...))`, and `Template(name, status, body)` with an optional MIME type. The positional forms still compile and behave as before.
- **Go: every adapter has the same surface.** `App.IsTrap` takes the framework's request type in all three adapters (`*http.Request`, `*gin.Context`, `echo.Context`); on Gin this replaces the promoted `IsTrap(any)`, which remains as `app.Sentry.IsTrap`. All three answer from the route the framework matched (net/http asks the mux), as Echo's already did, so a real route such as `POST /users/me` next to a trap `POST /users/{id}` is not reported as a trap and keeps its CSRF protection. net/http gains `Use(sentry, mux)` like Gin and Echo. `Sentry.IsTrap` now uses a cached index instead of rebuilding every trap's configuration on each call.
- **Go: adapter plumbing is no longer public API.** `MethodAllowed`, `QueryToMap`, `MapToQuery`, `ReadBody`, `ReadBodyLimit`, `ResetBody`, `DetectHoneyFields`, `DetectHoneyFieldsAny` and `TriggerWatchEvent` are unexported, and the deprecated `ParseMultipartFields` / `RebuildMultipartBody` are removed. Adapters now reach the core through an internal package; `InspectWatch`, `TriggerTrapEvent` and `SetBodyResolver` stay exported but deprecated, only so that adapter modules older than this release still build.
- **Docs:** a per-framework table (request object, body parsing, CSRF, known limits) in Supported Frameworks; every example app flushes events with `close()` on shutdown.

### Fixed: full SDK review

- **Django under ASGI returned 500 on every request** once Sentry was installed (a synchronous view hook in an async chain). Django traps with path parameters, Flask traps with `<id>` / `<path:p>`, and Tornado traps with `:id` / `{id}` / `<id>` / catch-alls now answer with the decoy instead of 500 or 404.
- **A deeply nested honey value bypassed detection** (Python at ~1000 levels, Node at ~5000): the sanitizer overflowed the stack, so no event was sent and the field reached the app. Values nested more than 32 levels deep now always alert and are recorded with `"<nested>"` in place of the too-deep part, identically in all three SDKs.
- **Async callbacks:** an `async` `identify_user` (or other callback) could crash a Node process with an unhandled rejection, and in Python silently made every hit anonymous. Callbacks must be synchronous; one that returns a promise or coroutine is logged once and treated as failed. A failing Python `override_source_ip` now falls back to the framework's own client IP, as in Node and Go.
- **Traps that silently replaced real routes** are now detected and fail loudly: Express routes in mounted sub-routers and Django `re_path` / converter / `include()` routes.
- **Watches that never fired:** Starlette/FastAPI routes declared with converters (`{id:int}`, `{p:path}`) or a trailing slash; Express routers mounted under a parameterised path. Express sub-apps and Koa routers wrapped in `koa-compose` / `koa-mount` cannot be seen and now produce an accurate warning.
- **Multipart:** Litestar and Sanic parse multipart by the RFC delimiter (a value containing `--boundary--` could hide later fields) and report and strip file parts sent under a watched name. A watched multipart route no longer breaks a later `request.body` in Django.
- **Gin:** the first request to a watched route could be inspected before the app's middleware ran, so its event lacked the user; coverage is now decided at bootstrap. Bootstrap no longer mutates `gin.DebugPrintRouteFunc` (a data race). `app.Handler()` honours `UseH2C`, and Echo's `StartH2CServer` goes through trappsec.
- **Echo** now reports watched requests that an earlier middleware rejects. **net/http** no longer inspects requests the mux answers with a redirect.
- **Tornado** no longer re-encodes unrelated non-UTF-8 query and form values, and a trap conflict now fails on every request instead of being logged once while leaving traps and watches uninstalled.
- **Consistency:** two `watch()` calls for the same path merge in Python and Go as in Node; a field sent once is a scalar in every framework (Starlette, Flask and Django passed a one-element list); `is_trap` follows one shared set of path rules, including catch-all last segments (`tests/conformance/is_trap.json`); Node renders a repeated object reference in full instead of `"[Circular]"` and sorts JSON keys like Python and Go; a failing trap answers with its own unauthenticated response in every Python framework.
- **Robustness:** a negative, zero or non-finite `heartbeat_interval` no longer spins a busy heartbeat loop (Python, Node); Node drops events for an invalid webhook URL instead of retrying each one; Starlette/FastAPI cap inspected bodies at 10 MiB.
- **Performance:** `is_trap` is a cached index in Python and Node, as in Go, instead of rebuilding every trap per call (about 400 µs per call with 56 traps in Python). Gin no longer route-matches every request twice once a watch exists (unwatched routes: 570 ns and 5 allocations before, about 60 ns and none now). Express wraps only watched routes, and only NestJS enables AsyncLocalStorage. net/http skips the extra mux lookup when there are no watches.
- **Simplicity:** shared Python multipart helpers (`integrations/_formbody.py`) replace three copies, one trap fallback in core replaces five, Node's body/query inspection lives in `_common.js`, and the Go adapters share their bootstrap guard, request accessors and warnings in `internal/adapter`. Dead code removed in all three SDKs; `index.d.ts` declares `logger`, `service`, `environment` and `hostname`.

### Fixed

- **Docs:** `identify_user` examples returned `user_id` / `id`, but the SDKs read only `user` and `role`, so copied examples never produced alerts. Fixed everywhere. The Node quickstart now logs the port it listens on, and the `add_webhook` example no longer targets Slack with a raw payload (use `add_slack`).
- **Never break or stall the host request:** all user callbacks (`identify_user`, `override_source_ip`, callable defaults, dynamic bodies, webhook templates) are guarded and fall back safely; exceptions inside trappsec's own watch/trap code are logged and the request proceeds.
- **Honey-field detection:** canonical value matching (`1` = `1.0`, `true` = `"true"`); duplicate and multi-valued query/form fields can no longer bypass a watch and are fully stripped without data loss on other fields; own-property rule lookup in Node (`constructor`, `__proto__` never match); case-insensitive JSON keys in Go; top-level JSON arrays are inspected and odd body shapes never crash.
- **Traps:** no longer silently shadowed by app routes; Express, Koa and NestJS-Express insert them after ordinary middleware and before the first route; Express recurses into sub-routers; exact duplicates of app routes fail loudly at bootstrap; Django traps are CSRF-exempt; string trap bodies are sent raw regardless of mime type.
- **Responses:** `respond(...)` honors falsy-but-provided values (`{}`, `""`, `0`, `false`, status 0); Node template cloning preserves function bodies; default responses are resolved at bootstrap so configuration order no longer matters.
- **Honey-field detection, cross-language parity:** list and object defaults now match equal values in Node (previously every request alerted) and in Python (`[True]` no longer matches `[1]`, `["5"]` now matches `[5]`). A one-element list that equals a list default is clean in Python and Node. Go now records a one-element list in `found_fields[].value` as its element, as Python and Node already did.
- **Go: JSON bodies with trailing data no longer bypass a watch.** Only the first JSON value was inspected and a body with anything after it was skipped, but Gin's and Echo's binders (`json.Decoder`) read the first value and ignore the rest, so `{"is_admin":true} x` reached the handler without an alert. Every top-level value is now inspected and stripped; an unparseable tail is kept byte-for-byte.
- **Python: webhooks after `fork()`** (gunicorn `--preload`): a forked worker no longer re-sends events that were still queued in the parent, and starts with a fresh queue, lock and HTTP session.
- **Events, cross-language parity:** every SDK now sends exactly the documented keys per event. Go no longer adds `reason`, `metadata` and `found_fields` to every event, and sends `found_fields: []` rather than `null` on an empty `watch_hit`. Python no longer adds `intent: null` to `watch_hit`. Object values in `found_fields[].value` render as compact JSON with sorted keys in all three (Python dropped its spaces, Node now sorts keys, Go no longer HTML-escapes `<>&`). Go truncates `path` and `user_agent` to 1024 characters plus `...`, like Python and Node.
- **Sanic: events record the client IP.** The default extractor read `request.remote_addr`, which Sanic fills only from trusted proxy headers, so without proxy configuration every event had `ip: "0.0.0.0"`. It now falls back to the socket address (`request.ip`). The Sanic example had the same fallback, and the net/http example recorded `host:port`; both are fixed, and the e2e suite now requires the exact client address.
- **Node: honey query fields are removed from the raw URL too.** Express, Fastify and Hapi stripped watched query keys only from the parsed query, so `req.url` (Express), `req.raw.url` (Fastify) and `request.url` (Hapi) still carried them and a proxy or handler reading the raw URL saw the honey field. They are now removed there as well; Express keeps `req.originalUrl` as received.
- **Fastify: traps and watches declared after `await app.register(...)` were silently ignored.** Awaiting any `register` loads queued plugins, which installed trappsec's routes and watch map early. Traps are now installed when the app boots (`ready()`, `listen()`, `inject()`), and the watch map is built on first use.
- **CSRF protection no longer disables traps:** Flask-WTF's `CSRFProtect` answered POST traps with 400 and no event; trap views are now exempted automatically. For other CSRF middleware, new `is_trap(request)` (Python, Node) and `Sentry.IsTrap(req)` (Go) tell it to let traps through.
- **Tornado: a trap's 405 no longer has an `Allow` header.** Tornado's own 405 for a method a handler does not implement has none, so the extra header told a trap apart from a real route. The e2e suite now compares how a trap and a real route answer DELETE, PUT and OPTIONS on every framework.
- **Node: route-level body parsers no longer hide honey fields.** Watches inspected the body when the route was entered, before route-level middleware ran, so `app.post('/x', multer().none(), handler)` (Express, also with an app-level `express.json()` on Express 4), `router.post('/x', bodyParser(), handler)` (Koa), `@fastify/multipart` registered after Sentry (Fastify) and `AnyFilesInterceptor` / `FileInterceptor` (NestJS on Express) let honey fields reach the handler without an event. Body inspection now finishes once the body is parsed, right before the handler, and reports what was seen if the request ends first.
- **Value matching and truncation, last parity gaps:** Python and Go now write floats exactly as JavaScript does when comparing a form/query string to a numeric default (`"1e-7"` matched in Node only; Python expected `"1e-07"`, Go `"0.0000001"`). Node truncates long strings by code points like Python and Go instead of UTF-16 units, so it no longer splits emoji.
- **Traps under CSRF protection:** Litestar traps are now excluded from `CSRFConfig` (they returned 403 and emitted nothing, so the trap was silently disabled). Echo gains `App.IsTrap` to use as the CSRF middleware's `Skipper`.
- **Gin: routes in groups created before `InstallSentry` are watched.** A route added to such a group never got the watch middleware, so honey fields reached the handler with no alert. `App.ServeHTTP` now inspects any watched route until it has seen the middleware cover it.
- **Go: unreachable watches are logged.** At bootstrap the net/http, Gin and Echo adapters log every watch that matches no registered route (a typo, a missing group prefix, or a route inside a mounted sub-mux, with the mount pattern to watch instead).
- **Examples:** Gin and Echo no longer trust forwarded headers for the client IP, and the uvicorn-based examples run with `proxy_headers=False`; the e2e suite now checks that a forged `X-Forwarded-For` is not recorded as the client IP.
- **Supported versions are now stated and tested:** the oldest framework versions the integration tests pass on are listed in Supported Frameworks and checked in CI (Python 3.10 for each Python framework, Node 20 for the Node ones). The Litestar and Sanic integrations log an error at startup on versions below 2.13 and 24.6, where honey fields are missed.
- **Tests:** shared conformance fixtures in `tests/conformance/` (value matching, honey-field detection, `safe_value`, event keys) run in the Python, Node and Go unit tests. The e2e suite verifies every webhook's HMAC signature and exact event keys, catches duplicate or late events, and reports unsupported multipart as skipped. `tests/package/run.sh` (new CI job) smoke-tests the built wheel, sdist and npm tarball.
- **Slack:** `&`, `<`, `>` are escaped in all request-derived values; a non-empty fallback `text` is always set.
- **OpenTelemetry:** span event attributes use valid OTel types (nulls dropped, other values stringified).
- **Go:** default client IP in Gin/Echo no longer trusts spoofable proxy headers; `http.Server{Handler: app}` is supported; request body size is bounded.
- **Logging:** Python no longer calls `logging.basicConfig`; Node logging has no escaped template literals.
- **E2E harness:** `requires-python` lowered to `>=3.10`; `--log-dir` and a CSV summary are implemented; Node examples are installed (`--install`, on in CI); `--kill-port-blockers` is opt-in; bare `except` and duplicate imports removed.

### Changed

- **Webhook signing:** requests now carry `x-trappsec-timestamp` and `x-trappsec-signature: sha256=<hex HMAC-SHA256(secret, "<timestamp>.<body>")>`. Update receivers; the old bare-digest header is gone. Heartbeats are signed the same way. See the Event Reference for verification snippets.
- **Delivery is asynchronous:** webhook/Slack events go through a bounded queue (1000) with background retries (max 2); when full they are dropped with a rate-limited warning.
- **Events:** all keys are always present, with `null` for absent values (including `user`/`role` on signals). `found_fields[].type` is `"query"` or `"body"`. Recorded values are sanitized and truncated; `path` and `user_agent` are capped at 1024 characters.

### Added

- `close()` / `Close()` to stop heartbeats and flush pending deliveries.
- Public, idempotent `bootstrap()` / `Bootstrap()` in every integration, also invoked lazily on the first request where the framework allows.
- `trigger()` in Node (emits `trappsec.rule_hit`, parity with Python and Go).
- Docs: Threat Model, Production Deployment and Tuning False Positives pages; expanded API and Event references.
- Integration rules R15 to R23 (bootstrap, async delivery, value matching, multi-value, sanitization, duplicate traps, IP extraction, CSRF, responses).
- CI for Python (3.9, 3.11, 3.13), Node (18, 20, 22, 24), Go (core and adapters) and e2e; release-triggered publish workflows with test gates and environments; Go module tagging workflow; Dependabot; issue and PR templates; CONTRIBUTING.
- Removed the hard-coded version badge from the README.
